# Task contract (P10)

Migrations014–015 extend the fixed P07 task child and migration013 reading foundation. Catalog30tables/369columns/39public functions. No generic entity/workflow platform or finance/publicity approval is introduced.

The canonical UUID is work_items.id = tasks.work_item_id. Task assignee and work owner are the same member, enforced by deferred database constraints. Creator remains the immutable created_by auth-user stamp; Created by me uses that stamp, not the changing owner. Owner/assignee display-name snapshots retain attribution. A task may reference an independently editable, same-term deliverable through parent_work_item_id. P14 now supplies canonical contribution/task same-term FKs (docs/synergies.md). Arbitrary standalone linking remains closed. Agreed output/owner/date/units/type require renegotiation; notes/progress remain scoped. read_task exposes contributionId and the editor locks material fields. No implicit parent access or invented acceptance.

Task fields: active same-term assignee, optional receiving unit, exact collaborators, checklist with up to50 unique UUID/text/boolean items, fixed task_type (ordinary/review_required/governed), blocked reason, completion evidence and typed state. The original deadline is immutable. Current deadline is a date-only YYYY-MM-DD or an explicitly offset ISO timestamp; dates must be finite. Date-only targets end at23:59 Manila. Done/cancelled tasks leave the overdue view.

## Commands

- `create_task(p_term_id,p_data,p_request_id)` creates work+child, creator's exact read grant, collaborators, attributed revision, idempotency receipt, redacted audit and pending outbox atomically. Actor derives from the current authenticated core membership. Own self-assignment is allowed; another person's assignment requires current scoped management of the receiving unit. Lead selection requires an active deployment. Parent linkage requires independent edit permission; it grants no parent/sibling access.
- `update_task(p_work_item_id,p_data,p_expected_version,p_request_id)` requires current exact task edit access. Assignees/shared editors can change notes and checklist checkmarks; changing checklist structure/title/safe summary/deadline requires management authority. Management means current unit/exact-work management, or self-created work still owned by its creator. Being the new assignee alone never grants deadline/assignment management. Assignment, scope, parent, classification and task type are not changed here. A reason is mandatory. Submitted review content must return to In progress before editing.
- `assign_task(p_work_item_id,p_data,p_expected_version,p_request_id)` requires an authorized assigner and explicit current receiving-head authority for other-person/cross-unit assignment. A receiving head without source-unit authority needs exact task edit scope before acceptance. Each assignee/collaborator must be active, same-term and deployed to the receiving unit when one is specified. Assignment changes the canonical owner/assignee together; creator is unchanged. It resets To do/checkmarks/current completion evidence, with earlier revisions preserved. No absent future agreement is treated as accepted.
- `transition_task(p_work_item_id,p_data,p_expected_version,p_request_id)` accepts todo/in_progress/blocked/ready_for_review/done/cancelled. Progress requires current task participation or management. Blocked requires an attributed reason. Done requires every checklist item checked, no unresolved blocked state and final evidence. review_required additionally needs a ready-for-review submission and independent current scoped-manager review; self-review fails. Governed Done is closed pending authoritative approval interfaces. No task transition records FIN/MCD/deliverable acceptance. Terminal records cannot be edited through these commands.

p_data is a closed feature-specific JSON object; no actor/owner override or arbitrary script is accepted. Create/update fields: title, summary, body, leadUnitId, parentId, dueOn, dueAt, assigneeId, assignedUnitId, collaborators, checklist, taskType, classification, reason. Update may omit parentId to avoid exposing a restricted parent. Assignment fields: assigneeId/assignedUnitId/collaborators/reason. Transition fields: state/reason/evidence. Payload size and field/array limits are checked. Generic P07 create_work_item/update_work_item reject tasks, closing the incomplete draft bypass.

P07 expected-version row locking and actor/command/key idempotency apply. Exact retries return the original receipt; changed payload under a reused key fails. Denials/stale edits produce no successful change. task_revisions stores private reason/content/checklist/evidence/owner/unit/collaborator snapshots with actor/time; immutable audit/outbox contain only safe field markers and references. Direct task/collaborator/revision mutations are denied; revisions are append-only even for ordinary trusted SQL updates.

## Reads / frontend

`read_tasks(term,view='assigned',page=1)` provides assigned/created/watching(shared)/overdue/unit views,20-row stable deadline/UUID pagination and counts from the same authorized records. List payloads exclude task body/checklist/evidence/parent IDs. `read_task(UUID)` requires exact participant/detail access; denied/missing/wrong-kind all return null. Parent UUID appears only with independent parent summary access. `task_options(term)` derives current actor, active member choices (directory authority or self only) and unit metadata. New assignee/collaborator and configured source/receiving/exact-work managers gain task scope only, never implicit parent/sibling authority. Current deployment/role/expiry is rechecked. Guests retain exact granted read-only task scope and cannot enter My Tasks or run commands.

TasksPage/TaskDetail/TaskEditor use real SDK RPCs. UUID links survive sign-in; view/page state is URL-backed. Loading/error/empty/denied/archived/terminal states are explicit. Saved version/update time comes from the database. Stale edits retain unsaved input; uncertain replies freeze controls and retry the identical key/payload. Assignment/progress cannot silently discard unsaved note/checklist/date edits. No private drafts enter browser storage. The editor changes date-only targets and preserves existing timestamp targets; RPCs support reasoned timestamp changes. Evidence is a bounded reference/note; actual file verification belongs to the file interface.

P15 TaskDetail embeds independently authorized read_contribution terms for agreed tasks: accepted revision, output, criteria, effort, owner and deadline. Pending negotiations are absent. Parent links require separate parentId authorization. My Tasks retains the same canonical task with a contributions link; arbitrary task-to-contribution editing remains closed.
