# P07 work-record spine implementation plan

> **Execution:** Follow the user-authorized execution method with available tools. No agents/chats/worktrees. Existing codex/core-build-checkpoints branch; reviewed checkpoint push remains authorized.

**Goal:** Deliver minimal relational work records with exact scoped access and safe draft commands, without later workflow features.

**Architecture:** work_items carries safe summary metadata; four fixed typed child tables carry participant-only draft detail with deferred exactly-one-child integrity. Status, grants, append-only audit, actor/command/key idempotency and pending outbox rows are relational and enforced by PostgreSQL. Public RPCs derive actor, lock/check expected versions and commit business/audit/outbox/retry result together.

**Tech Stack:** Existing React19/TypeScript6/Vite8/Supabase, pnpm11 and isolated PGlite SQL harness; preserve installed versions.

**Spec:** TEDx-Core-Dashboard-Implementation-Plan.md section6 Command/API contracts and section8 work items/audit; build-prompts/07-work-record-spine.md; BUILD-CONTRACT.md.

## Global Constraints

- React, TypeScript, Vite, Supabase; planned Cloudflare static hosting, no deployment in P07.
- Event April17,2027; Asia/Manila; budget PHP0; synthetic local data only.
- RLS before exposed reads; no client service keys; fixed schema/security invariants.
- Same-organization/term references; immutable semantic status categories; no direct status/owner/approval writes.
- Actor from authenticated subject, expected version and persistent request UUID; redacted transactional audit/outbox.
- P02–P06 provider/privacy/authority/human blockers remain; no fake external proof.

## Review Focus

- Exact child/grant access cannot reveal parent IDs, siblings, restricted titles or private payloads.
- Record role/invitation FKs cannot expand into unit/term authority or outlive current membership/sponsor/expiry.
- Concurrent versions and repeated actor/command/key requests cannot duplicate work, audit or outbox events.
- Denied/invalid mutations roll back every business/retry/audit/outbox effect.
- Typed-child mismatch/orphan and cross-term references fail even through trusted SQL; clients have no mutation grants.
