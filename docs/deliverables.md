# Deliverable reading contract (P08)

Migration `20261024001100_deliverables.sql` extends the fixed P07 child. `deliverables.work_item_id` remains the canonical output UUID. New fields are phase_key, outcome, acceptance_criteria, is_blocked and safe_blocker_summary. Outcome/criteria/body are participant details; phase/blocker are safe summary fields. Existing child actor/time/version triggers apply. Original deadlines remain immutable on work_items.

`deliverable_units` records planning involvement with same-organization/term foreign keys to the child and units, forced RLS and authenticated read only when that work summary is permitted. It neither grants work access nor records accepted contributions. P10 owns contributions. P08 adds no mutation RPC, direct write grant, approval transition or authoring form.

Authenticated-only, actor-derived read RPCs with empty search_path:

- `list_deliverables(p_term_id, p_phase=null, p_unit_id=null, p_owner_id=null, p_blocked=false, p_overdue=false, p_involves_my_unit=false, p_review_pending=false, p_page=1, p_page_size=20)` returns `{items,total,page,pageSize,options:{phases,units,owners}}`. Pages are 1–10000; page sizes 1–50. Rows, counts and options derive from permitted, nonarchived deliverables. Filters combine with AND. Lead/support matching uses EXISTS, so one canonical output never duplicates. My-unit matching uses current active dated deployments and nonarchived units. Pagination orders deadline then UUID.
- `read_deliverable(p_work_item_id)` returns the safe summary plus `details:{outcome,acceptanceCriteria,body}` only with independent P07 detail access; otherwise details is null. Missing, wrong-kind and denied IDs all return null. Archived records retain permitted stable detail links with an archive indicator.

Summary DTOs contain ID/term/title/safe summary, owner ID/retained name/current active flag, lead unit, supporting units excluding the lead, phase, current/original date or timestamp, server-computed overdue, safe blocker, updatedAt, archivedAt and parent version. The fixed next action names the owner or requests reassignment when inactive. Date-only deadlines become overdue after the Manila day ends. updatedAt is the greatest parent/child timestamp; unit-association administration has no client path in this step.

Readiness is only `pending_gate_verification` or `blocked_provisional`. Gates are exactly `{finance:'pending_assessment',publicity:'pending_assessment',acceptance:'pending_definition'}`. Gate-review-pending includes every permitted output until an authoritative contract replaces it. Neither safe prose nor criteria constitutes approval. P29 owns authoritative acceptance; no percentages or automatic approvals are produced.

`src/features/deliverables/api.ts` validates RPC DTOs and sanitizes failures. The real gateway wires the SDK to `/deliverables` and `/deliverables/:UUID`. URL filters are phase/unit/owner/blocked/overdue/mine/review/page; changing filters resets page. Canonicalized list state is retained on in-app back links. Invalidated options get generic unavailable labels. Loading, empty, error, denied, archived and participant-detail-withheld states are explicit. Strict UUID detail links survive sign-in, including exact-scope guests; guests cannot enter the core list and return to `/shared`. Database authorization remains authoritative.

The seed adds one clearly fictional shared output only after this child extension exists; it activates no identities or memberships. With Vite running, `node scripts/preview-p08.cjs` serves a separate loopback-only, in-memory PostgreSQL preview at `http://127.0.0.1:5174/deliverables`, with a prominent simulated-sign-in banner. It uses actual pages/adapter/read RPCs and a fixed synthetic subject. Its two-RPC transport is a script-only harness, never a production endpoint. Restarting discards data. `node scripts/verify-p08.cjs` uses a separate disposable port5175 database and closes it after checks.

P08_A1–A3 are exercised by `pnpm test:deliverables`, five frontend tests and the browser verifier. These prove local PGlite/auth-shaped SQL and routed rendering, not Supabase17/JWT/PostgREST. P02–P07 provider, official type, parallel-session, authority/privacy and human acceptance blockers remain in their ledgers.

## P09 authoring (supersedes the earlier read-only boundary)

Migration012 adds workflow_state (proposed/draft/in_progress/submitted/accepted/cancelled), criteria_revision and final_evidence; immutable deliverable_revisions retain versioned outcome/criteria, owner, deadline, reason, final/review evidence and actor/time. No public gate writes. deliverable_gate_assessments accepts only trusted, justified not_applicable dispositions for finance/publicity/contributions, bound to the exact work version and a current independently authorized assessor. P29 owns governed decisions; clients cannot waive them.

`create_deliverable(p_term_id,p_data,p_propose,p_request_id)`, `update_deliverable(p_work_item_id,p_data,p_expected_version,p_request_id)`, `transition_deliverable(p_work_item_id,p_action,p_reason,p_evidence,p_expected_version,p_request_id,p_criteria_revision=null)` reuse P07 actor/key/payload receipt locking and transactional redacted audit/outbox. p_data is a closed object: title/summary/body/ownerId/leadUnitId/phase/outcome/criteria/dueOn/dueAt/classification/reason. Exactly one finite deadline is required. Owner/unit must be active and same-term. Reason required for edits; original deadline/classification immutable. Criteria/outcome changes increment criteria revision and invalidate prior work-version assessments. Generic work-item commands reject deliverables.

Configured current committee.manage (unit scope; PMs need an explicit applicable scoped assignment) authorizes direct creation, proposal approval, assignment/reassignment and independent acceptance. Members propose only themselves; owners submit final evidence. Draft/in-progress edits, start, submit, reasoned return to draft and cancellation before acceptance are bounded actions. Acceptance requires matching current criteria revision, explicit reviewer evidence, active owner, no blocker and all three current-version/current-authority trusted clean assessments. Direct API status/child/gate writes, self-acceptance and unresolved mandatory gates fail. Accepted workflow state does not imply global release/finance/publicity readiness; P08 readiness stays provisional.

`read_deliverable_authoring(p_term_id,p_work_item_id=null)` derives current permitted fields/actions/options and a scoped derived inactive-owner queue. Ordinary members receive only themselves as owner options; configured managers may select active same-term members. Scoped managers gain detail/edit access to their lead-unit deliverables only. Original owner remains recorded until explicit reassignment; no owner is silently erased. Public list/detail adds workflowState. Guests receive no authoring context.

DeliverableEditor is embedded in existing list/detail routes. Create visibility defaults restricted; changes retain it. Form supports Manila date-only targets; existing timestamp targets are preserved (RPC supports reasoned timestamp changes). Reload explicitly discards unsaved edits; stale conflict retains text. Uncertain replies freeze fields and retry the same key/payload; malformed receipts never become success. Evidence references/notes do not verify files. No draft/profile content is stored in the browser.

`pnpm test:deliverable-authoring` owns P09_A1–A3; `node scripts/preview-p09.cjs` serves labeled fixed-synthetic-manager authoring at port5176 with Vite5173 running. `node scripts/verify-p09.cjs` uses disposable5177. P02–P08 external gates remain in their ledgers.
