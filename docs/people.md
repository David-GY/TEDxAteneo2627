# People directory — P06 partial contract

`read_people_directory(p_term_id)` returns a JSON array of one row per permitted active core member: `id`, `name`, `contact`, `units[]`, `roles[]`, `course`, `year`, `phone`, `externalContact`. It delegates access to P03/P04 `read_directory`, so current verified school identity, membership, term and directory capability remain authoritative. Organization email is returned only for the exact school domain. Private course/year/phone/external contact are independently null unless the owner has shared each field. Raw identity/profile grants are unchanged. Unit and role assignments must be current; archived units are excluded. Private fields are not searchable in the UI.

`read_process_contacts(p_term_id)` returns active units with plain names and `primary[]`/`backup[]` contact identities from effective deployments. Empty arrays mean unassigned; the UI explains the missing contact rather than inventing one. Contacts must also be in the permitted current directory. Multiple contact holders remain explicit. No affiliation input affects either query. These read-only projections add no writes, invitations, messages, external service calls or real roster data.

Both RPCs are fixed-search-path security definers, authenticated-only, with explicit capability gates. No broadened raw table grants. Guest subjects receive empty arrays; P05 continues routing guests away from `/people`. This is deny-default containment, **not completion of guest own/shared contacts**. No shared-record scope exists until P07. Former members do not expose current private profiles; historical display-name attribution still requires later work-record integration.

`src/features/people/gateway.ts` batches the two real RPCs; `pages.tsx` extends the existing shell/components. Failure returns a generic error and retry; search filters only already-permitted name/unit/role fields. Help/task links remain usable with blank optional affiliation. Fixtures live only in tests and browser-intercept HTML.

Not delivered yet: own profile editor; optional skills/pronunciation/affiliation disclosure; separate versioned/idempotent server commands for private values and sharing choices with redacted audit; guest own/shared contacts; historical attribution integration. Existing P03 direct own-profile writes are not a substitute for those P06 commands. No profile editor or fake save button is exposed by this partial slice.
