# Task dependency contract (P16)

Migration021 adds task_dependencies and immutable task_dependency_events. Catalog44tables/494columns/63public functions. Canonical contribution tasks use this same graph; no duplicate work or task linking is introduced. Table RLS is enabled/forced before exposure; no raw table grants or direct client writes.

add_task_dependency(predecessor,successor,type,required,expected_predecessor_version,expected_successor_version,reason,key) checks both tasks independently: same term, current edit and management (configured task manager or self-created owner), active term and nonarchived endpoints. Types are finish_to_start/informational; informational cannot be required. Reject self-edges, duplicate live pair/type and cycles across all live edge types. Graph commands lock a term-scoped transaction advisory key before work/receipt locks and cycle queries. READ COMMITTED is required; snapshot-isolation transactions fail with40001 rather than read a stale pre-lock graph.

remove_task_dependency(edge,expected_predecessor_version,expected_successor_version,reason,scope_exception,key) rechecks both endpoints and versions. Removing required gates requires explicit scope_exception=true and current configured scoped management of both tasks, including receipt retries. Cancelled/archived predecessors never count as completion; a permitted reasoned scope exception can remove their gate. Removal is a tombstone plus immutable event, not history deletion. Redacted audit/outbox and P07 actor/key/payload receipts are atomic; private reasons remain in independently scoped history.

Required unfinished finish-to-start predecessors block In progress, Ready for review and Done. Informational and optional links do not. Shared locking wraps existing task commands and P14 response activation before their row locks. Existing validation/assignment/FIN/MCD/review/parent gates remain. A trigger also rejects reopening a Done predecessor while an active/ready/done required successor relies on it; accepted material renegotiation may therefore need a coordinated dependency scope change first. No automatic rescheduling, state advancement, acceptance or approval occurs. Original deadlines remain untouched.

read_task_dependencies(task,search='') independently checks task detail access, each predecessor, each successor and each history source. Hidden endpoints expose only neutral restricted/readiness booleans, never UUID/title/state/reason/count. Search offers up to50 matching manageable same-term predecessors, with no hidden totals. The read includes permitted next-step links, current versions, removal authority and immutable history. read_task adds dependencyBlocked; contribution reads and views reuse it. Task Dependencies forms retain safe drafts on stale/failure; uncertain replies freeze edits/refresh/competing task authoring and retry exact payload/key. Successful changes refresh contribution terms without discarding unsaved task edits; explicit whole-task reload discards those edits and refreshes task versions.
