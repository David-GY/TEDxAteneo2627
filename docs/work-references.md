# Task and deliverable references (P36-R1)

Local source migration045 implements TASK-001 / DEL-001 references. UUID primary keys, UUID routes, work versions, creation/update receipts and existing FIN/MCD/general request tracking remain unchanged. This migration is not deployed to the hosted project.

`work_reference_counters` and immutable `work_references` are forced-RLS/raw-denied tables. Per-term/per-kind issuance uses the existing term readiness lock plus a reference namespace lock and locked monotonic counter. A creation trigger issues the reference in the same transaction as the work/child/audit/outbox. Failed creation rolls it back; an identical command retry returns the original receipt and never issues a second reference. Numbers grow beyond999, never truncate, and cannot be rewound or recycled. Retiring/renaming work does not change its issued reference. The term UUID qualifies the namespace; its current unique organization term label is presentation context.

The migration takes a work-table DML lock while installing legacy namespace markers and the creation trigger, then numbers the first100 existing rows per namespace in deterministic created_at/UUID order. Each unfinished legacy namespace remains closed to new creation while its existing work stays readable through the original UUID links. Reference metadata may remain null until backfill reaches that row; clients never fabricate a number. An approved server operator can resume `app_private.backfill_work_references(term,kind,batch_size)` in **separate committed READ COMMITTED transactions**, default100/max500. Repeat until complete=true; repeated complete batches process zero. On55P03/NOWAIT conflict, roll back that whole batch and retry after the editing transaction finishes. Do not reset counters, skip missing legacy records, flip the marker manually, or expose this private operation as a member API. Provider application remains subject to the existing deployment gates; no hosted backfill was run here.

Existing authorized deliverable summary/detail, task detail/list/owned-task and Overview projections carry optional `reference:{value,termId,termLabel}`. Missing fields support the older hosted projection and mean reference unavailable. `resolve_work_reference(term,kind,reference)` returns only the currently authorized summary ID/kind/title/reference; missing, wrong-term, hidden and expired-guest cases return the same null without counts. Knowing a reference grants no permission. Private predecessor/issuance/backfill functions have no public/anon/authenticated/service-role EXECUTE grants; raw reference/counter tables have no client grants.

Primary lists remain title first. Detail Copy reference copies `TASK-027 · term label`; Copy link copies the unchanged absolute UUID URL. The term is shown separately, clipboard failure retains selectable text/link and never announces success, and a form without confirmed saved work has no issued-reference control. Exact global search remains P43; form editing/publication is not part of R1.

Local named tests: `pnpm test:work-references`, `node scripts/verify-p36-references.cjs`, work-references Vitest plus task/deliverable/Overview tests. They cover an actual044→045 upgrade, interrupted/resumed backfill, existing request IDs/pinned pairs, failed outbox rollback, old/new identical retries, rename,999/1000/1001, queued client submissions, distinct term namespaces, scoped resolver/guest expiry, actual clipboard, old links,320px/long labels/44px/keyboard. Queued PGlite calls are not proof of independent PostgreSQL sessions. Real Supabase17/JWT/Storage/concurrency, institutional/privacy/human/restore gates remain open.
