Terms contain output, criteria, small/medium/large effort, finite date-only dueOn, reason and optional independently readable finalized sourceManifestIds. Receiver must be a different active delivery committee in the same term. Material amendments create immutable revisions while old accepted work remains active. Proposals invalidate parent-version gate evidence. Duplicate live/accepted output per parent/receiver fails, including counters.

respond_to_synergy(agreement,action,expected_version,expected_revision,owner_id,terms,reason,key) accepts accept/decline/counter. Receiver may accept with an active same-term deployed owner, decline with reason, or counter with revised terms/owner. Requester explicitly confirms that exact counter revision and cannot substitute its owner. Initial requester confirmation delegates owner selection to immutable receiver confirmation. Both confirming heads must retain current deployed committee.manage authority at activation; actors must differ. Titles confer no authority. Stale parent/lead/agreement/revision fails. Actor derives from session; locks acquire parent then agreement. Exact caller-key receipts, one atomic redacted audit/outbox per command; no external delivery.

Acceptance creates one contribution whose UUID is the canonical task/work UUID, actual same-term FKs, owner=assignee, scoped grants and immutable task history. Deferred constraints verify canonical linkage and both confirmations. Accepted amendments update the same task, reset progress/current evidence and retain original deadline/history. Generic edits cannot rewrite agreed output/owner/date/units/type; existing editor locks these fields. Notes/progress follow current permissions. Arbitrary standalone contribution linking remains closed. Done never grants deliverable/FIN/MCD acceptance. Parent acceptance is fail-closed for pending agreements/contributions until the actual later contribution acceptance interface.

Forced RLS precedes exposure; no client writes/raw negotiation SELECT. read_synergy returns explicitly shared terms/history/confirmations only to current eligible heads. Parent content stays hidden; parentId requires independent summary access. Source IDs independently require can_read_manifest. Counters preserve source references without disclosing them. read_contribution requires task detail access and returns active terms, no pending negotiations or whole-parent/file access. Contribution SELECT columns and read_task wrapper preserve these boundaries. read_task adds contributionId.
