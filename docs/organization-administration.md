# Organization administration contract (P33)

Migration041 (`20261026224004_organization_commands.sql`);100tables/1036columns/134public functions. No production roster, role, unit or institutional authority is seeded.

## Interfaces and authority

`read_organization(term)` returns unit identity, aliases/merge links, core roster organization contacts, dated deployments, permitted ordinary deliverable options and structural history. `preview_organization_change(term,action,values)` returns current version/fingerprint, reviewed differences, authorized open-work links, assigned structural reviewer capabilities, access effects and an explicit blocked outcome. `publish_organization_change(term,action,values,expected_version,fingerprint,reason,request_id)` rechecks current authority and impact before applying a command.

All three require current core membership, workspace.read, term admin.configure AND roles.manage. Writes require an active term. Actor/approver identity derives from auth.uid/current membership; there is no actor argument or impersonation. Public wrappers have empty search_path, fixed typed/allowlisted actions and authenticated-only execute; helpers are private. No arbitrary SQL/scripts, raw case read, authority-role creation or optional-profile override exists.

A neutral restricted announcement control spine versions structural publications for the term. Current READ COMMITTED term serialization plus expected control version and a catalog/state fingerprint reject stale previews. Existing actor/key/payload receipts provide exact retry; source changes, permanent aliases/merge links/origin references, immutable structural metadata, redacted audit and neutral outbox commit atomically. Late audit/outbox failure rolls everything back. Metadata diffs retain labels/responsibilities/IDs/dates/status and omit copied roster email, private profile values and case payloads. The five new tables (organization_control/unit_aliases/unit_links/organization_changes/work_unit_origins) force RLS and deny raw API grants. No transport/schedule is installed or invoked.

## Supported changes

- Unit add/edit: UUID stays fixed; code/name become permanent term aliases. Delivery and review flags are independent. Removing a responsibility is blocked by active obligations/live routing. Codes/names cannot steal another unit's reserved alias.
- Archive/merge: the source archives only after active work/reviewer/service obligations are resolved. Merge records an immutable source→target identity link; source deployments/roles cease to be effective through the existing archived-unit predicates. It copies **zero** deployments, roles or record grants and moves **zero** private case contents. Target scope never inherits source authority. Historic private work and case receiving-unit references remain on the original UUID. Merged targets must be distinct/current in the same term; archived sources cannot create cycles. Deep links use UUIDs; old alias lookup resolves the original unit card, which links to the merge target without granting target access.
- Approved roster add/edit: exact student.ateneo.edu email; new member/term record is explicitly approved but has no auth linkage, invitation or implicit role grant. Existing inactive/invited account lifecycle is not silently changed across terms. Existing member identity/email/auth linkage and private affiliation/course/sharing fields cannot be overridden. Roster edit changes display name, term state and dates only. Suspension/shortening is blocked by active ownership/review/service obligations and administrative continuity; self-suspension or removing a role-bearing administrator is refused. Role custody/revocation remains a separate permission-management concern.
- Dated deployment add/edit/revoke: same-term current core member/current unit, explicit type/from/to/state, validity within roster dates and current approver attribution. Existing member/unit/type identity stays fixed. A label does not create any role assignment, but a deployment may activate an already assigned unit role: the preview exposes existing scoped capabilities and publication requires explicit confirmation. Removal/shortening with unresolved obligations is blocked. No implicit FIN/feedback/MCD authority, roster privilege or guest successor is created.
- Explicit ordinary deliverable remapping: requires edit and manager authority for both old/new units plus an eligible named owner; reuses the established update_deliverable command with its expected work version and unchanged content/dates/criteria. Restricted/governed, FIN/publicity-linked, child-work or synergy-bearing deliverables are refused/blocked. A first immutable origin row preserves the original unit; existing deliverable snapshots/decisions/grants remain unchanged. This is not a migration adapter for private tasks, FIN, feedback, requests or typed approval policies.

P33_A3 is the conservative **refusal path**: unsafe archive/head removal is explicitly blocked and the old unit/deployment remains active. Case state is not mass-frozen and no replacement approver is invented. Existing authorized work/reviewer workflows must resolve the obligation first. Empty-unit archival/merge is supported; protected active case migration is deliberately absent.

## Impact and UI

The existing /admin route uses src/features/admin/organization. No illustrative list of committees is hardcoded. Units, current active heads/primary/backup contacts, approved roster, dated deployments, ordinary work options and published history come from the scoped backend. Current contact rendering checks roster/account/deployment dates/state and archived-unit state. No private profile disclosure is required.

Draft fields are local and publication is explicit after preview plus access-effect confirmation. Changing fields invalidates that preview. Date-only display editing preserves exact original instants when the date fields are unchanged. Stale conflicts preserve fields; uncertain outcomes lock an identity-bound exact command for retry. Navigation/focus/visibility/30-second refresh rechecks current access and hides prior rows on pending/error. This is a permission explanation and synthetic preview, not unrestricted role impersonation.

Work titles/links are projected only after independent current work access; restricted work titles are neutral even when a link could be authorized. Unlisted restricted obligations produce a generic blocker, not private titles/counts/amounts/payloads. Reviewer lists describe structural role assignments, not a public enumeration of private case assignments. The impact fingerprint hashes operational identity/version references without returning their private values. Aliases and unit_links are absent from every authorization predicate. Files continue using their own existing work/origin/Edge/Storage checks.
