# CSV task-import contract — P45 continuation

November 3, 2026. Ordinary-task server imports are implemented locally; P45 remains in_progress. Roster import and scoped record export remain unavailable. No migration/provider deployment, real data, institutional approval, schedule or external delivery is activated. All P44 actual gates remain open independently.

Source056 `20261102171003_task_imports.sql` is the server boundary (equivalent to proposed supabase/functions/imports paths); no duplicate Edge CRUD bypass is added. Four public RPCs are read_task_import, save_task_import, preview_task_import and commit_task_import. Existing create_task/update_task commands perform every task mutation. Read/save/preview/commit and successful receipt retries derive the actor and require current active-core workspace authority, admin.configure AND roles.manage, plus committee.manage and a current deployment in the selected unit. Administrative permission alone grants no task/roster/case access.

Four app_private tables hold actor-owned sessions, immutable input revisions, permanent source bindings and immutable commit receipts. All force RLS and deny raw anon/authenticated/service access. Neutral public announcement control spines contain fixed metadata only, protected from generic announcement/work edits and deletes. Import guards preserve unrelated delete semantics (regression verified). Only the author can read a draft under current term/unit authority; receipt reads also recheck current task-detail scope. The recent-draft list is bounded20. Data is not cached in browser storage. Draft/history retention/disposal needs approved policy before real activation; do not treat in-memory preview persistence as a backup or provider proof.

Server schema validation repeats the fixed task catalog independently: header/mapping/rows only, 2–32 unique named columns, at most50 records/200,000 JSON bytes, string cells bounded2,000 characters, unique destination/source mapping, required source key/title and no authority/financial headers. Role, identity-provisioning, arbitrary query/script and financial fields cannot become commands. Malformed global schema fails before saving. Per-row preview checks title/date, duplicate keys, unique existing task targets, selected committee/current alias, permitted exact reference, and unambiguous visible deployed person name. Hidden/missing references have the same generic repair response and no target ID/reference. Names outside permitted unit membership are indistinguishable from unknown names. No school-email/UUID/capability transcription is required. Ambiguous people require the task page or leaving the new-task person blank for the actor; no privilege or membership is inferred.

The chosen committee UUID plus normalized list name and case-sensitive source key form a permanent deduplication namespace, shared across authorized actors but with private drafts. Keep all three for retries/new files. A source key cannot be rebound to another task; each existing task appears once in a file/list. Existing refs/UUIDs are never renumbered, and new refs come from the existing server allocator. Reusing the list/source keys in a new session yields unchanged or explicitly previewed updates, not duplicate creation.

Blank person on new work means the current actor, shown by name before confirmation. Blank date/person on existing work preserves it. Only title/untimed-date changes on ordinary To do tasks without completion evidence are supported. Existing assignment, description, checklist/progress, state, original deadline and issued ref remain intact. Assignment changes and timed deadlines require the task page. Imports cannot change class, unit, parent, workflow, roles, FIN/MCD or completion. Untouched fields are reconstructed from the current authorized source, never accepted from client commands.

Save uses expected draft version and exact actor/key/payload receipts, appending private history and redacted audit/outbox. Preview returns row errors, exact permitted before/after values and a server-derived hash including current source versions/resolution. An invalid row blocks the whole file. Commit requires expected draft version/hash, locks the term graph/readiness and referenced work, recomputes the plan, then calls authorized task commands. Immutable bindings/receipts and parent audit/outbox commit atomically with children. Late outbox failure rolls back tasks, references, bindings, receipts and events. Exact retry rechecks current authority before returning success. Stale draft/source versions reject; no overwrite is inferred from a lost response. Parent audit/outbox contain fixed field codes and opaque IDs, not raw CSV/list/row contents.

UI: local mapping/repair stays available. Only explicit Save sends mapped task input; opening the panel reads own permitted draft metadata/unit choices. Saved drafts can be replaced into the editor through an explicitly labelled control; recheck keeps local edits. Input changes invalidate server review, whose labels include actual unit/list and named people. Confirmation is disabled until all current server rows pass and the user checks the exact-change acknowledgment. Unknown mutation outcomes lock the same payload/key and offer Retry identical request. Known errors preserve safe edits; permission denial clears private preview/context. Scope/account changes unmount drafts. Saved JSON key order is normalized for semantic dirty checks, so resume does not force another save. Receipt links lead with title/ref and retain term. Roster preparation has no commit path. Exports remain closed.

Verification: scripts/test-task-imports.cjs and verify-p45-task-imports.cjs exercise actual isolated SQL and compiled browser recovery, including malformed repair, a successful commit whose response is deliberately dropped, same-key receipt recovery, reload/resume and repeat-file deduplication. These are synthetic, not actual Supabase/JWT/concurrent-session, school/privacy/retention, Excel/Sheets or human UAT acceptance. The encoder below remains a pure helper; no scoped record export exists yet. Next CONTINUE P45: roster-candidate operations through P33 reviewed commands and authorized scoped exports, then remaining spreadsheet/adoption/provider checks. No P46.

# CSV preparation contract — P45 partial

October 30, 2026. Local preparation only. `/admin/imports` is linked from Organization administration and requires current `admin.configure` AND `roles.manage` in the loaded workspace context. This is a presentation restriction, not a server import authorization boundary. The component has no data gateway, lookup, commit or record export API. No migration or provider change accompanies this batch.

`src/features/imports/csv.ts` owns the bounded parser, template definitions, local validation and human-viewing CSV encoder (equivalent to the proposed imports/exports codec paths). `CsvPreparation.tsx` owns transient mapping/review. Proposed `supabase/functions/imports/*` is intentionally absent until the authorized command interface is built. No placeholder RPC reports success.

Parser: UTF-8 text supplied by paste, optional BOM, comma separators, CRLF/LF/CR records, doubled quotes, embedded quoted newlines. Malformed quotes/nulls, more than 200,000 characters, 32 columns or 500 data records fail before preview. Record numbers count logical CSV records including the header. Input decoding/upload and downloadable templates are not implemented.

Templates use fictional people and ordinary names, never required UUIDs/capability codes. A source key is an operator-supplied stable retry label, not a database identity. Local duplicate keys flag every matching row; roster email comparison ignores case. Required destinations, unique headers/mappings, cell counts, bounded values, real ISO calendar dates and exact school email domain are validated. Authority/financial source headers are rejected even when ignored. Unknown unmapped columns are explicitly listed and have no effect. This does not resolve an identity, prove eligibility or reserve a record/ref.

Local review is all-or-nothing: any error blocks the whole file. All mapped values remain visible as escaped text; input/mappings survive local repair, while editing either invalidates the old review. Changing type keeps input but clears mapping/review. Account, term or capability changes remount/deny the page. Data is not persisted to browser storage or sent by this component; navigation/reload loses it. Keep the original file. Durable resumable imports are still required.

Issued reference strings and named people/committees are retained as unresolved hints. Blank cells never imply permission to clear an existing value. Existing UUIDs, original dates and issued references must be preserved by the future server resolution/command path. There is no exact before/after claim until that path resolves current records and versions. Import confirmation and scoped record export remain visibly unavailable, including after local validation passes.

The pure `spreadsheetCsv` encoder emits BOM/CRLF, quotes every cell and doubles quotes. It prefixes an apostrophe for formula initiators (=,+,-,@ and full-width variants), including leading whitespace/format characters and leading control characters. This deliberately changes dangerous human-viewing values and is not a lossless machine round trip. It has no caller exporting private records. Encoding regressions pass; actual Excel/Sheets import and save/reopen are unverified. [OWASP CSV Injection guidance](https://community.owasp.org/attacks/CSV_Injection) explicitly describes spreadsheet-specific limitations; do not claim a universal guarantee from quoting/encoding tests.

Next interface: server-owned private import sessions, current scoped lookup of existing authorized identities/work only, exact diff with expected versions, durable source identity/receipts and retry recovery, immutable history and atomic redacted audit/outbox. Reuse P33 roster and P10 task commands, P34 current authority, P43 safe title/ref/term reads and P44 scoped report boundaries. Test unauthorized/hidden lookups, role escalation, wrong term, malformed fields, stale versions, replay versus changed-payload key reuse and late audit/outbox failure before implementation. Choose and test explicit atomicity. Repeat all catalog/schema validation on the server. Never execute arbitrary queries or grant privileges from CSV. Scoped exports need current server authorization including joins/counts and preserved UUID/ref/term/date context. Financial imports remain separate authorized reconciliation; no bidirectional Sheets sync.
