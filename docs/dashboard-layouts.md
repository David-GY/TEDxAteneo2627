# Dashboard layouts and private operational views

P40 source049 is local only. It repairs the missing shared site/layout publication adapter without changing P34 authority or P35/P38 service/process commands. Local catalog:49 migrations,120 tables,1192 columns,160 public functions. Hosted remains43/107/1098/140. P35/P36/P39 remain incomplete; no P41 or deployment is authorized by this implementation.

`presentation_actor` derives the current core membership through `request_actor` and P34-backed `has_capability`. Current term `admin.configure` permits term/site and role/unit layout targets. A delegated `committee.manage` publisher also needs an active current head deployment to the exact target unit; it cannot edit another unit, a role or the term/site. Target IDs must exist in the same term; units must be unarchived and roles active. Guests cannot use these configuration/personal-account RPCs. Their existing shared-work/help/device arrangements remain intact.

`presentation_drafts`, `presentation_controls`, `presentation_versions`, `operational_views` and `operational_view_versions` force RLS and deny raw API-role access. Public mutation/inspection functions allow authenticated execution only; current authority is checked before exact-retry replay. No permission or deployment record is created. The private service-role/anonymous API surface stays closed.

The closed layout schema repeats the seven-widget client catalog on the server: waiting, tasks, deliverables, working, reviews, calendar and resources; version1, ordered unique IDs and wide/compact sizes only. It accepts no query, capability, work payload, route, arbitrary options, disabled-module widget or FIN widget. Empty secondary views are allowed because next actions/help are outside the configurable area. Work remains projected through the existing independently authorized `read_overview`; calendar/resources open independently authorized workspaces.

The separate site schema repeats P39's plain-text captions/order, bounded text/link/card blocks, fixed destinations and two supported accent candidates. It excludes licensed identity/logo/asset overrides, raw HTML/scripts, permissions and arbitrary routing. Server support for this schema is not P39 contextual Edit Mode, shell loading, branding application or approved-logo/MCD completion.

Publication RPCs:

- `read_layout_targets(term)` returns only currently permitted named targets. No raw identifier entry is required by `/admin/layouts`.
- `read_presentation_configuration(term,kind,targetKind,targetId,before?)` reauthorizes and returns current publication, only the actor's draft, and50 immutable history rows with a next-before cursor. Other eligible publishers see history but never each other's private drafts.
- `save_presentation_draft(term,kind,targetKind,targetId,definition,baseVersion,expectedDraftVersion,key,rollbackVersionId?)` validates the complete schema and exact same-target rollback source. It serializes through the existing term readiness lock and rejects stale base/draft revisions. Saving explicitly rebases retained input against the newly read publication. Draft saves store an actor/key/payload-hash receipt, without copied content in a business outbox.
- `preview_presentation_configuration(draft)` validates the actor-owned saved definition and returns exact before/after definitions, stale-base flag and review hash binding draft ID/revision, definition, base/current version, previous definition and rollback lineage. No real-user impersonation or data access simulation occurs; the four layout examples remain fictional.
- `publish_presentation_configuration(draft,expectedDraftVersion,reviewHash,reason,key)` rechecks target/current authority before replay and fresh mutation, serializes, rereads the draft, revalidates and verifies the hash/base. It creates an immutable version through the existing neutral restricted announcement spine and `finish_work_command`, with atomic redacted audit/outbox/receipt. A late outbox error rolls back definition, version and receipt. Rollback is a new publication; intervening history and work remain unchanged.

`/admin/layouts` uses the existing identity/scope-bound decision memory and global leave/reload guard. Save, preview/diff, acknowledgment, reason and publication are explicit. Changes invalidate preview. Restore selects a historical definition as a private draft; it never publishes automatically. Conflicts preserve inputs for deliberate refresh/rebase; uncertain commands lock target/layout edits and retry the identical payload/key. Transient read failures hide editors but retain safe process-memory inputs. Confirmed permission loss clears the corresponding client draft store. Older history responses are generation-bound so they cannot overwrite a newly selected scope. Retired definitions show a warning, offer a safe repair draft and cannot be restored as valid history.

`read_my_layout_configuration(term)` resolves current live unit memberships and P34-provenance-backed live role assignments; exact-work roles do not become whole-dashboard role defaults. One matching unit layout takes precedence over one matching role layout, then the term default, then built-in defaults. Multiple matches at the same level fall through to a broader default and set an explicit ambiguity flag. No arbitrary UUID wins. A retired published catalog definition returns a safe default plus a repair flag. The client also validates each received definition.

Existing scoped device preferences take precedence over published defaults. Members can explicitly Use published default to clear that preference. Selecting a named view applies only the closed widget arrangement to the device; it does not copy authoritative work or grant access. The member overview never requires setup.

`save_operational_view(term,viewId,name,definition,archived,expectedVersion,key)` creates a private named view or appends a new owned version, including archival. Only the current actor's views are returned. Names are bounded plain text; metadata contains no work titles/record IDs/counts/data payload. The stable view ID is not a work ID and never authorizes data. Saves use current membership, version/idempotency checks, the same term lock and atomic redacted audit/outbox. History is immutable. Up to20 records per actor/term, including archived records; the UI states this bound. The current UI creates named arrangements and archives them; it does not offer renaming or in-place updating. Retired named definitions remain visible for archival but cannot be applied.
